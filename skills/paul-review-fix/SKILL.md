# Review Fix

리뷰의 뒤편. **판정은 여기서 다시 하지 않는다** — 기준의 정본은 `paul-review` 다.

반영이 끝나는 조건은 "고쳤다"가 아니라 **리뷰 항목과 결과가 짝이 맞는 것**이다. 짝이 안 맞으면 사용자가 리뷰를 다시 읽어 대조해야 한다.

## 0. 경계

| 하는 것 | 하지 않는 것 |
|---|---|
| 리뷰에 있는 항목을 고친다 | 리뷰에 없던 것을 같이 고친다 |
| 필수는 반영, 권고는 묻는다 | 권고를 조용히 반영한다 |
| 동의 안 되는 지적에 근거를 쓴다 | 근거 없이 따르거나 조용히 뺀다 |
| 항목마다 결과를 되짚는다 | "다 반영했습니다" 로 끝낸다 |

반영하다 **새 문제를 발견하면 말만 하고 고치지 않는다.** 그건 다음 리뷰의 몫이다 — 여기서 판정하면 정본이 갈라진다.

## 1. 입력을 먼저 확정한다

| 소스 | 어디서 읽는가 |
|---|---|
| 같은 세션의 `paul-review` 출력 | 그 출력의 항목 목록 그대로 |
| GitHub PR 리뷰 | `gh pr view --comments` · `gh api repos/{owner}/{repo}/pulls/{n}/comments` — **코멘트 id 를 함께 붙잡는다** |
| 사람이 말로 준 지적 | 한 줄로 재진술해 확인받은 뒤 항목화 |

**항목 목록이 없으면 만들지 않고 묻는다** — 무슨 리뷰를 반영할지. 리뷰를 대신 만드는 건 `paul-review` 다.

항목마다 식별자를 붙인다(코멘트 id · 필수1 · 권고2). 되짚을 때 짝이 맞아야 한다.

## 2. 반영 전에 가른다

| 등급 | 기본 동작 |
|---|---|
| 필수 | 반영한다 |
| 권고 | 반영 여부를 묻는다 — 항목마다 묻지 않고 **묶어서 한 번** |
| 동의 안 되는 것 | 고치지 않고 근거를 쓴다 |
| 요청 범위 밖 | 분리해 별도 작업으로 제안한다 |

**리뷰어도 틀린다.** 근거를 정본에서 못 대는 지적은 고치지 않고 그렇게 답한다 — 반박도 반영의 일부다. 조용히 따르는 건 반영이 아니라 굴복이고, 다음 사람이 왜 이렇게 됐는지 못 찾는다.

## 3. 반영

`agentic-workflow` 의 스텝 실행을 **항목 단위로** 적용한다.

1. **같은 원인끼리 묶는다** — 항목 하나 = 커밋 하나가 아니다. 원인 하나 = 커밋 하나
2. 필수 먼저, 권고는 **승인된 것만** 뒤에
3. 묶음 하나가 끝나면 그 레포의 검증을 돌린다 (`agentic-workflow` 스텝 검증). 실패하면 출력과 함께 보고하고 멈춘다
4. **지적된 줄만 바꾼다** (`NORMS.md` 3장)

고치다 근처를 "같이 개선"하는 순간 리뷰어가 무엇에 동의했는지 사라진다. 리뷰 반영은 리팩토링을 여는 문이 아니다.

커밋은 명시적 요청이 있을 때만. 형식은 `paul-taste`. scope 는 원 작업과 같게 두고, 설명은 **무엇을 고쳤는지**를 쓴다 — `리뷰 반영` 만 쓰면 나중에 아무 정보가 없다.

## 4. 되짚기

**로컬 리뷰** — 표로 보고한다. 표기는 Spec 과 같다(`agentic-workflow`).

```
| 항목 | 결과 | 위치 |
|---|---|---|
| 필수1 any 단언 | ✅ | packages/x/foo.ts:31 |
| 권고2 파일 분할 | ⏸ | 승인 대기 |
| 권고3 이름 변경 | ❌ | 실물 용어가 이쪽이라 유지 |
```

✅ 반영 · ⏸ 보류(사용자 판단 대기) · ❌ 반영 안 함 — **❌ 에는 근거를 한 줄 붙인다.**

**PR 리뷰** — 커밋을 푸시한 뒤 각 코멘트에 답글을 단다.

- 답글은 **그 코멘트 스레드에**(`in_reply_to`) 단다. PR 본문이나 새 코멘트에 몰아 쓰지 않는다 — 리뷰어가 자기 지적 옆에서 봐야 한다
- 링크는 **푸시된 커밋에만.** 로컬 해시는 남의 화면에서 404 다
- 답글 문구·형식의 정본은 `/paul:reply-review` 다 — 코멘트 하나씩 여는 사용자 호출 전용 스킬. 부를 수 없으면 **어디를 어떻게 고쳤는지 한 줄 + 커밋 링크**
- **반영 안 한 코멘트에도 답글을 단다** — 이유를 쓰는 것도 답이다
- **resolve 는 사용자가.** 스레드를 대신 닫지 않고, 대신 머지하지 않는다

## 판정

1. 이 항목이 **리뷰에 실제로 있었는가** — 없으면 내가 만든 것이다
2. 권고를 **승인 없이** 반영하고 있지 않은가
3. 바뀐 줄이 전부 **지적된 줄인가**
4. 항목마다 결과가 **하나씩** 붙었는가 — 빠진 항목이 없는가
5. 링크를 붙인 커밋이 **푸시됐는가**
6. 동의 못 하는 지적에 **근거를 썼는가**, 그냥 따랐는가

## 안 하는 것

| 하지 않는 것 | 이유 |
|---|---|
| 리뷰에 없던 것을 함께 고치기 | 반영이 리팩토링으로 번진다 |
| 권고를 조용히 반영 | 사용자가 동의한 범위가 넓어진다 |
| 새 문제를 여기서 판정 | 기준의 정본이 `paul-review` 와 갈라진다 |
| 항목별 결과 없이 "다 반영했습니다" | 대조 비용을 사용자에게 넘긴다 |
| 안 푸시한 해시로 링크 | 링크가 죽는다 |
| 대신 resolve · 대신 머지 | 리뷰를 닫는 권한은 리뷰어에게 있다 |
