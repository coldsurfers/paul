`$ARGUMENTS` = 사용자가 대충 던진 한 줄. 예 — `/paul:autoprompt 이거 왜 느려` · `/paul:autoprompt 로그인 폼 만들어줘`

`$ARGUMENTS` 가 비어 있으면 **무엇을 다듬을지 먼저 묻는다.** 직전 대화에서 질문을 골라 잡지 않는다.

프롬프트 엔지니어링(배경 설명 · 목적 명시 · 제약 나열)에 드는 시간을 없앤다. 사용자는 떠오르는 대로 한 줄만 던지고, "완벽한 질문으로 다듬는 일"은 여기가 대신한다. 요점은 **왕복 없이** 결과를 내는 것 — 애매한 걸 되묻는 순간 이 스킬의 존재 이유가 사라진다.

## 절차

1. **원문 확인** — `$ARGUMENTS` 가 원문이다. 표면 문구보다 실제 의도를 우선한다.

2. **재해석** — 아래를 채워 완전한 프롬프트로 재구성한다. 새로 리서치하지 않고 **이미 접근 가능한 컨텍스트**에서 추론한다.

   | 항목 | 어디서 채우는가 |
   |---|---|
   | 배경 | 대화 히스토리 · 최근 diff · 열려 있는 파일 · `CLAUDE.md` · `AGENTS.md` · `docs/` · 직전 작업 |
   | 목적 | 이 질문 뒤에 실제로 원하는 결과물 — 설명인가 · 코드 수정인가 · 의사결정인가 |
   | 제약 | 스택 · 컨벤션 · lint 룰 · 이미 확정된 결정 · 건드리면 안 되는 범위 |
   | 산출물 형식 | 코드 diff · 설명 · 표 · 체크리스트 · 짧은 답 중 무엇인가 |
   | 빈틈 | 추론으로 못 채우는 것은 **되묻지 말고** 가장 합리적인 가정을 세워 명시한다 |

3. **투명성** — 답변 맨 위에 재해석 요약을 한두 줄로 보인다. 본 답변보다 길면 안 된다.

   ```
   > 재해석: [배경 한 줄] · [목적 한 줄] · [제약/가정 한 줄]
   ```

4. **실행** — 재구성한 프롬프트를 기준으로 실제 작업을 한다. 파일 읽기 · 검색 · 도구 호출은 평소대로. 이 스킬이 바꾸는 건 **질문을 읽는 방식**뿐이고, 작업 방식은 `NORMS.md` 와 나머지 스킬이 그대로 소유한다.

## 되묻는 경계

되돌릴 수 없는 작업의 **대상**(어느 브랜치 · 어느 PR · 어느 환경)처럼, 잘못 추측하면 실질적 피해가 나는 필수 정보가 없을 때만 `AskUserQuestion` 을 쓴다. 취향 · 스타일 · 디테일 수준의 모호함은 전부 2번 방식으로 가정하고 진행한다.

재해석이 어긋났으면 사용자가 잡아준다 — 그때 정정을 반영해 다시 답한다. **왕복을 줄이는 것이지 되묻기를 영원히 막는 게 아니다.**
