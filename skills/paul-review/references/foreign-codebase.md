# 남의 코드베이스 리뷰

`paul-review` §0.5 의 확장. **내가 쓰지 않은 코드**를 볼 때 연다 — 오픈소스 첫 PR · 합류 첫 주 · 인수인계받은 레포 · 장애 초동.

정본이 `paul-*` 이 아니라 **그 레포 자신**이라는 전제는 §0.5 와 같다.
여기 있는 건 **정본을 찾는 실행 절차와, 도구가 못 잡는 함정 목록**이다.

---

## 0. 제1규칙 — 읽기 전에 지도를 그린다

처음 보는 레포에서 가장 비싼 실수는 **1번 파일부터 정독하는 것**이다.
한참 읽고 나서 *"아, 저건 원래 있던 거였네"* 를 만나면 앞의 독해가 통째로 날아간다.

**지도가 먼저다.** 무엇이 주어진 것이고, 무엇이 이번에 쓴 것이고, 계약이 어디 적혀 있는가.

---

## 1. 네 단계를 섞지 않는다

| 단계 | 하는 일 | 절대 하지 않는 일 |
|---|---|---|
| **지도** | 주어진 것 / 쓴 것 경계 긋기 · 설정 · 계약 · 테스트 훑기 | 판정 |
| **수집** | 본문을 읽으며 **후보를 쌓기만** 한다 | 가르기 · 문장 다듬기 |
| **가르기** | 후보 → 필수 + 권고. 묶을 건 묶는다 | 새 파일 열기 |
| **쓰기** | 출력 형식대로 쓴다 | 새 지적 추가 |

**수집과 판정을 섞는 것이 가장 흔한 실패다.** 읽으면서 판정하면 **처음 본 것에 닻이 내린다** —
한참 뒤에 만난 진짜 문제가 목록 아래로 밀리고, 그 순서가 그대로 상대에게 전달된다.

**쓰기에 들어간 뒤 새 지적을 추가하지 않는다.** 추가하려면 가르기로 돌아가 **전체를 다시 세운다.**
그러지 않으면 마지막에 붙은 항목만 가르기를 거치지 않은 채 섞인다.

---

## 2. 지도 그리기

§0.5 의 1~5 를 이 순서로 실행한다.

```bash
git log --oneline -20                # 무엇이 원래 있던 것이고 무엇이 최근에 들어왔는가
ls -a && cat package.json            # 봉인된 의존성(file:*.tgz) · 스크립트 · 매니저
cat .eslintrc* biome.json tsconfig.json 2>/dev/null   # 레포가 이미 깔아둔 레일
```

| 봐야 할 것 | 무엇을 아는가 |
|---|---|
| `*.tgz` · `lib/` · `vendor/` · `_*/` | **손대면 안 되는 영역.** 여기 있는 걸 새로 만들었으면 그게 지적이다 |
| 서버 핸들러 · 목 데이터 · 요청 예시 | **도메인 규칙의 정본.** 검증·거절 조건이 전부 여기 있다 |
| API 응답 타입 · DTO | 경계면. 화면과 대조할 기준 |
| 테스트 | 그 레포가 지키기로 한 선은 어디인가 |
| 같은 종류 파일 셋 | A·B 는 하는데 **C 만 빠진 것** |

**프론트를 보더라도 서버 쪽을 먼저 읽는다.** 클라이언트가 무엇을 잘못하면 **서버가 거절하는지**가 거기 적혀 있다.
그게 필수 수정의 1순위 후보다.

## 3. 도메인 함정 — 도구가 못 잡는 것

타입이 통과하고 린터가 조용한데 **배포하면 틀리는** 자리들이다.

| 함정 | 어떻게 드러나는가 | 어떻게 확인하는가 |
|---|---|---|
| **양쪽 계산** | 클라이언트가 계산한 값을 서버가 **재계산해 거절**한다 → 두 식이 같아야 한다 | 서버의 검증 분기를 찾아 클라이언트 계산식과 나란히 놓는다 |
| **인덱스 결합** | 배열 둘이 **순서로만** 묶여 있다. 한쪽이 늘면 조용히 어긋난다 | 두 배열을 같이 쓰는 지점에서 길이가 보장되는지 본다 |
| **파생된 필수 조건** | "필수" 가 플래그가 아니라 **규칙**(타입이 X 이거나 최소개수 > 0)이다 | 서버 검증의 조건식을 클라이언트에서 찾는다 |
| **단위가 이름에** | 1/1000 정수 · 센트 단위. 그대로 그리면 **스케일이 통째로 틀린다** | 숫자가 경계를 넘는 지점마다 단위를 묻는다 |
| **레이아웃 값으로 데이터 순회** | 열 개수 같은 표시용 값으로 데이터를 돈다 | 지금 데이터라서 **우연히** 맞는지 본다 |
| **상태 분기 누락** | 계약에 있는 상태(진행중 · 빈 상태 · 404)를 화면이 안 다룬다 | 계약이 낼 수 있는 상태를 전부 세고 화면과 대조한다 |
| **UI 값 ≠ 도메인 값** | 화면용으로 가공한 값을 그대로 API 로 보낸다 | 입력값이 요청 바디로 가는 경로를 끝까지 따라간다 |

**확인법은 하나다** — 계약(서버·타입·목)에 적힌 규칙을 **클라이언트 코드에서 찾는다.** 없으면 후보에 올린다.

### 계약 말고도 도구가 놓치는 것

- **폴링·재시도에 상한이 있는가** — 없으면 실패 시 무한히 돈다
- **실패가 사용자에게 보이는가** — `return null` 과 `console.error` 로 때우지 않았는가
- **막았으면 왜 막혔는지 말하는가** — 버튼을 숨기는 것과 이유를 띄우는 것은 다르다
- **`{...props}` 를 빠뜨려 `onClick` 이 조용히 죽는가**

## 4. 가르기

수집한 후보를 **표로 옮긴 뒤** 자른다. 머릿속에서 자르면 처음 본 것이 이긴다.

| 후보 | 안 고치면 무엇이 터지는가 | 근거 위치 |
|---|---|---|

- **터지는 게 적히면 필수**, 안 적히면 권고다. 이 칸이 빈 항목은 **쓰지 않는다**
- 근거 위치가 **그 레포 안**이어야 한다. `paul-*` 도, "요즘은" 도 근거가 아니다
- 필수가 6개를 넘으면 5개로 줄이고 **"나머지는 같은 원인"** 을 한 줄로 쓴다 (`paul-review` §3)

**같은 원인으로 묶이는 것들을 먼저 찾는다.** 지적 12개가 "계약을 안 읽고 화면부터 짰다" 하나로 묶이면,
그게 12개보다 센 리뷰다 — 상대가 **한 군데만 고치면 12개가 같이 사라지기** 때문이다.

---

## 5. AI 로 훑을 때

넓게 훑는 일은 AI 가 빠르다. 다만 **가르기와 검증은 넘기지 않는다.**

| AI 가 해주는 것 | AI 가 못 하는 것 |
|---|---|
| 넓게 훑어 후보 쌓기 | **계약과 대조** — 코드만 주면 코드만 본다 |
| 일반적인 안티패턴 지적 | **도메인 판단** — 왜 이 값이 위험한지 |
| 수정 방향 초안 | **가르기** — 후보를 필수 몇 개로 줄이는 일 |
| 문장 다듬기 | **검증** — 코드에 없는 동작을 전제한 지적을 낸다 |

**AI 가 낸 항목은 전부 파일을 열어 확인한 뒤에만 쓴다.**
확인 안 한 항목이 하나 섞이면, 그거 하나 때문에 나머지 전부의 신뢰가 깎인다.

## 6. 리뷰 다음은 대화다

리뷰는 내면 끝이 아니라 **거기서 시작한다.** 남의 레포일수록 내가 못 본 맥락이 있다.

1. **항목마다 "왜 이게 먼저인가" 한 문장** — 우선순위를 말로 설명 못 하면 순서가 없는 것이다
2. **안 쓴 것 중 물어볼 것 두엇** — "이건 의도가 있어 보여 안 적었는데, 왜 이렇게 두셨어요?"
3. **물러날 선** — 반박이 들어왔을 때

| 상황 | 대응 |
|---|---|
| 근거가 레포 안에 있다 | **위치를 댄다.** "옆 모듈은 이렇게 합니다" + 파일 위치 |
| 근거가 내 취향이었다 | **물러난다.** "제 습관이었네요, 필수는 아닙니다" |
| 내가 못 본 맥락이었다 | **바로 접는다.** 버티면 그때부터 리뷰가 아니라 방어다 |

**전부 접는 것도 실패다.** 근거가 레포 안에 있으면 위치를 대고 버틴다 — 접힌 지적은 다음에 같은 자리에서 또 난다.

---

## 내기 전 점검

1. 필수가 **다섯 개 이하**인가
2. 모든 항목의 근거가 **그 레포 안**에 있는가
3. **못 본 범위**를 한 줄로 밝혔는가
4. 정답 코드를 대신 짜주지 않았는가 — **방향 한 줄**인가
5. 소리 내어 읽었을 때 **동료에게 하는 말**로 들리는가
