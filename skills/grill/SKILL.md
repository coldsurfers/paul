`$ARGUMENTS` 를 놓고 **정해야 할 결정을 전부 드러낸다.** 조용히 골라진 기본값이 남지 않게 하는 게 목적이다.

`$ARGUMENTS` 가 비어 있으면 무엇을 심문할지 먼저 묻는다.

**코드도 스펙 파일도 쓰지 않는다.**

## 결정 트리와 frontier

결정은 트리다 — 하나가 정해져야 그에 딸린 결정을 물을 수 있다.

**frontier** = 선행 결정이 이미 정해져서 *지금* 물을 수 있는 질문들. 한 라운드에 frontier 를 **전부** 던지고 답을 기다린다.

답이 오면 트리가 바뀐다. frontier 를 다시 계산해 다음 라운드를 던진다.

**다른 미결 질문의 답에 좌우되는 질문은 이번 라운드가 아니다.** 그건 다음 라운드 것이다 — 지금 물으면 사용자가 아직 없는 답을 가정하게 된다.

## 질문 형식

```
❓ **Q1 — {한 줄 제목}**
{선택지 · 트레이드오프. 길면 문단으로}

➡️ **추천:** {내 답} — {이유 한 줄}
```

**추천을 반드시 붙인다.** 사용자가 "다 응" 만 해도 진행되고, 내 기본값이 무엇이었는지 드러난다. 추천이 안 서면 그건 아직 사실이 부족한 것이다 — 아래를 먼저 한다.

## 사실은 내가 찾는다

환경에서 확인 가능한 것(파일 구조 · 기존 구현 · 의존성)을 사용자에게 묻지 않는다. 읽어서 답한다.

**결정만 사용자 몫이다.** 취향 · 우선순위 · 범위가 걸리면 반드시 묻는다.

광범위한 탐색이 필요하면 서브 에이전트를 띄우기 전에 **먼저 허락을 구한다** (`NORMS.md §0.5`). 탐색이 도는 동안 그 결과에 안 걸린 질문은 계속 던진다 — 막히지 않는다.

## 끝

frontier 가 비면 끝이다. 이때 **결정 요약**만 내고 멈춘다.

```
## 정해진 것
- {결정} — {근거 한 줄}

## 열어둔 것
- {미결} — {왜 지금 안 정해도 되는지}
```

다음은 `/paul:spec` 또는 곧장 Plan 이다 — **제안만 하고 넘어가지 않는다.**

## 하지 않는 것

- 답을 다 듣기 전에 구현으로 넘어가지 않는다
- 물을 게 없는데 라운드를 억지로 늘리지 않는다 — 진짜 갈림길만 묻는다
- 옵션이 하나뿐이면 옵션이라고 쓰지 않는다 (`agentic-workflow` 와 같은 규칙)
- 스펙 구조 · Plan 형식은 여기 쓰지 않는다 — `agentic-workflow` 가 정본이다
